# Ежедневная сверка МойСклад ↔ Битрикс24

Регламент вечерней сверки (20:00 МСК) заказов покупателей «Империи дверей».
Сверку выполняет Claude по расписанию: МойСклад читается и правится через
коннектор `imperia_dverey`, Битрикс24 через Zapier (приложение «Bitrix24 CRM»).
Детерминированная часть (поиск телефонов в тексте, нормализация, оценка
совпадения заказа и сделки) живёт в `contacts.py`, тесты в `test_contacts.py`.

```bash
python3 contacts.py extract "Магомадов Адлан  8-920-092-46-42"   # ["+79200924642"]
python3 contacts.py match order.json deals.json                 # auto / review / no_match
python3 -m unittest test_contacts
```

## Что проверяется

Окно прогона: заказы покупателей, созданные или изменённые за последние 26 часов
(`customerorder_list`, `sortBy=updated`), с развёрнутым контрагентом.

### 1. Телефон из комментария в графу «Телефон» (МойСклад)

Если у контрагента заказа пустое поле «Телефон», ищем номер в комментарии
заказа, в названии контрагента и в его комментарии (`contacts.py extract`).
Найденные номера записываем в «Телефон» контрагента в формате `+79XXXXXXXXX`
(несколько номеров через запятую). Заполненное поле не перезаписываем: если в
тексте есть другой номер, он попадает в отчёт.

### 2. Поиск сделки в Битрикс24

1. По каждому телефону контрагента: поиск контакта (`contact_search` по PHONE),
   затем его сделок (`deal_search` по CONTACT_ID).
2. Если телефона нет или контакт не найден: поиск сделок по фамилии и имени
   (TITLE и контакт), затем сравнение по адресу и сумме заказа.
3. Решение принимает `contacts.py match`:
   * общий телефон, или ФИО + адрес + сумма (±2 %) дают `auto`, данные переносятся;
   * частичное совпадение даёт `review`, ничего не пишем, сделка уходит в отчёт;
   * `no_match`: в отчёт «нет в Битриксе».

### 3. Битрикс24 → МойСклад

При `auto` заполняем в МойСклад только пустые поля: телефон, email и
фактический адрес контрагента, адрес доставки заказа.

### 4. МойСклад → Битрикс24

При `auto` дописываем в контакт (а если контакта нет, то в сделку) Битрикс24
недостающие данные из МойСклад: телефоны, которых там ещё нет, email и адрес,
если они пустые. Имена и существующие значения не меняем.

### 5. Ориентировочный срок доставки

Статусы, в которые нельзя переводить заказ без «Планируемой даты отгрузки»
(`deliveryPlannedMoment`): «Подтвержден», «Подтвержден Рассрочка»,
«Подтвержден ОПТ», «Завершен».

* Заказы, созданные начиная с 21.10.2026: если дата не стоит, статус
  возвращается в «Новый», а владельцу заказа ставится задача в МойСклад
  «Укажите ориентировочный срок доставки по заказу №…» со сроком на завтра.
* Более старые заказы без даты не трогаем, только считаем и перечисляем в отчёте.

Мгновенно (в момент смены статуса) запретить это можно только вебхуком
МойСклад на внешний сервер; ежедневный прогон ловит нарушения в тот же вечер.

## Правила безопасности

* Ничего не удаляем и не перезаписываем заполненные поля.
* Не больше 50 изменений за прогон; если нужно больше, прогон останавливается
  и в отчёте перечислено, что осталось.
* Каждое изменение попадает в отчёт: что было, что стало, по какому совпадению.

сохраняется в `/mnt/project-files/reports/sverka/ГГГГ-ММ-ДД.md`: сколько заказов

что требует ручной проверки.
